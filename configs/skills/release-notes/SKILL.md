# 📝 Release Note 寫作規範 (Release Notes Skill)

> **觸發情境**：撰寫版本 Release Note、更新 `CHANGELOG.md`、對外發布版本說明。
>
> ⚠️ **語氣原則**：本規範僅用於專案發布文案與 CHANGELOG。文字應具備發布感與專業清晰度，但所有效益、性能數據與技術宣稱必須由實際程式碼異動或測試數據支持，避免無法驗證的誇大形容詞。

---

## 1. 排版與風格要素

- **標準台灣繁體中文**：快取、本機、預設、資料夾、伺服器、後端、記憶體、登錄檔。
- **痛點與解法對比**：簡單說明過往問題或邊界情境，對比本次版本採用的新機制與效益。
- **視覺排版**：
  - **Emoji 表情符號**：大段落與特色標頭適當使用標示符號（🏆、✨、⚡、🛡️、🔍、📦）。
  - **重點粗體**：專有名詞、核心數據與功能名稱加粗。
  - **行內程式碼**：副檔名、檔案路徑、變數名稱、指令以 `` ` `` 包覆。

---

## 2. 文章結構與格式

發布文案建議包含以下結構：

### 區塊一：里程碑標題
```markdown
## 🏆 vX.X.X 里程碑：[10 字以內的核心功能總結]
```

### 區塊二：更新摘要
- **第一段**：簡明宣告版本里程碑與最關鍵的新功能或修復。
- **第二段**：說明原本遇到的邊界情境/痛點，以及本版透過什麼機制改善。

### 區塊三：重點更新特色 (Features List)
```markdown
## ✨ 重點更新特色

[Emoji] [功能名稱（技術亮點）]：
  - 實作細節（做了哪些邏輯調整、呼叫什麼 API 或機制）
  - 效益與表現（達成什麼穩定度、解決什麼潛在問題）
```

---

## 3. CHANGELOG.md 格式規範

專案 `CHANGELOG.md` 建議遵循 [Keep a Changelog](https://keepachangelog.com/zh-TW/1.0.0/) 結構：

```markdown
# 📝 更新日誌 (CHANGELOG)

## 🏆 vX.X.X (YYYY-MM-DD)
- **核心架構更新**：<一行摘要>
- **環境優化**：<具體說明>
- **修復與重構**：<具體說明>

## 🏆 vX.X.X-1 (YYYY-MM-DD)
...
```

**編碼規範**：`CHANGELOG.md` 應以無 BOM 的 UTF-8 編碼儲存，確保 GitHub Pages 或 CI 流程解析正常。
