# 專案交付前檢查

在使用者要求檢查、準備提交、推送、建立 PR，或確認 Web 專案可交付時使用。本 Skill 只負責蒐集驗證證據與提出修正建議；`commit`、`push`、建立 PR 與對遠端做任何寫入，都必須先取得使用者當次明確同意。

## 檢查順序

1. 先執行 `git status --short --branch`、查看遠端與目前分支。若工作目錄有未提交變更，不可直接 `git pull`；先回報並請使用者決定。乾淨時才可執行安全的 fast-forward pull。
2. 依專案既有設定執行最小且相關的檢查：優先使用既有 `package.json`、`pyproject.toml`、`requirements.txt`、Makefile 或 CI 腳本。不得為了測試而改寫產品設定。
3. 若為 Web 專案，啟動既有本機伺服器（或使用可安全載入的靜態頁面），用 Playwright 實際開啟頁面、等待載入、確認主要互動或關鍵元素，並記錄 console error、未捕捉例外及必要截圖。優先使用 role、label 與 `data-testid` 選擇器。
4. 執行 `git diff --check`，再檢視 `git diff` 與 `git status`，確認沒有不相關產物、意外格式錯誤或遺漏檔案。
5. 僅對即將提交的變更掃描常見敏感資料模式（API 金鑰、權杖、私鑰、密碼連線字串）。偵測到疑似值時不可在回報中重印完整內容；指出檔案與行號、建議移除或改用環境變數，並停止提交／推送。

## 交付判定與回報

- 清楚列出每一項檢查的「通過、略過、失敗」與實際執行的指令或測試情境。
- 只有在 Git 狀態合理、相關測試通過、Web 實測（若適用）通過、`git diff --check` 無錯誤且敏感資料掃描無警訊時，才可標示「可提交」。
- 沒有可識別的測試或 Web 專案時，標示略過原因，不可宣稱已驗證。
- 提交前顯示提交範圍與建議的 Conventional Commit 訊息；推送前確認遠端、分支與待推送提交。建立 PR 後回報連結與 CI／Actions 狀態。
